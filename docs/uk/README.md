# Aegis ECS — посібник користувача

Aegis ECS — це компактний **ECS-рушій на чистому GDScript** для Godot 4.4+.
Він створений для симуляцій, де тисячі й десятки тисяч об'єктів оновлюються
щокадру: юніти, снаряди, частинки ігрової логіки, натовп, bullet hell,
популяційні симуляції.

- **Без залежностей.** Ні GDExtension, ні C#, ні сторонніх аддонів.
- **Без прихованих алокацій** у сталому циклі кадру. Пам'ять росте лише через
  явний бар'єр.
- **Жодної ноди на ігровий об'єкт.** Дані живуть у `Packed*Array`.
- **Жодного шаблонного коду.** `EcsPackedStore` генерує всю обв'язку сховища.
- **Пакетні структурні операції.** Спавн і знищення — один виклик, а не N.
- **Вбудований інспектор.** Статистика кадру, пошук винуватця ривків і
  діагностика типових помилок — підключається одним рядком.
- **Безпечні посилання.** Упаковані generational handle захищають від ABA.
- **Експорт куди завгодно**, включно з iOS, без нативних залежностей.

## Шість правил безпеки

Стисла пам'ятка. Кожне правило розгорнуто у своєму розділі, а симптоми порушень
зібрані в [розділі 10](10-typovi-pomylky.md).

1. **Сирий id — для гарячого циклу, handle — для посилань між кадрами.** Runtime
   handle не можна писати у save/network як стабільний ідентифікатор.
2. **Структурні зміни — лише на sync points.** Не посеред системи; не можна
   кешувати щільний слот через цю межу.
3. **Реалізуйте `_relocate_dense()`** у ручному сховищі — забуте поле тихо
   змішає дані. Або беріть `EcsPackedStore`, де помилитися неможливо.
4. **`Packed*Array` у Godot 4 — reference semantics.** Локальний псевдонім перед
   циклом зберігає зміни без зворотного присвоєння.
5. **View/Query оновлюються до структурної зміни**, і склад сховища не можна
   міняти посеред обходу цього ж сховища.
6. **Пауза — це `delta == 0`**, а не пропуск кадру. Оголошуйте `requires_time`.

## Перевірка, що все працює

Аддон містить чотири самоперевірки. Запустіть їх із кореня проєкту, який містить
аддон:

```bash
godot --headless --script res://addons/aegis_ecs/example/minimal_example.gd
godot --headless --script res://addons/aegis_ecs/tests/test_advanced_ecs.gd
godot --headless --script res://addons/aegis_ecs/tests/test_ecs_features.gd
godot --headless --script res://addons/aegis_ecs/tests/test_inspector.gd
```

Кожна має завершитися рядком `RESULT: OK` і кодом виходу 0. Вони придатні для CI
як є.

Заміри продуктивності на вашій машині:

```bash
godot --headless --script res://addons/aegis_ecs/tests/benchmark_ecs.gd
```

Повна робоча симуляція, розібрана в [розділі 11](11-povnyi-pryklad.md):

```bash
godot --headless --script res://addons/aegis_ecs/example/colony_example.gd
```

## Що можна видалити

Модулі незалежні, зайве можна викинути:

| Тека | Що всередині | Залежить від |
|---|---|---|
| `ecs/` | Ядро: світ, сховища, системи, планувальник, готові системи | нічого |
| `spatial/` | `UniformSpatialGrid` — пошук сусідів | нічого |
| `time/` | `SimulationClock` — фіксований крок і масштаб часу | нічого |
| `math/` | `AngleMath` — доворот кутів | нічого |
| `debug/` | Збір статистики кадру, діагностика, звіти. Без нод | `ecs/` |
| `inspector/` | Візуальна панель. Вирізається з експорту | `debug/` |
| `example/`, `tests/` | Приклади й самоперевірки | усе вище |

### Про конфлікт імен

Аддон займає глобальні імена `EcsWorld`, `EcsComponentStore`, `EcsPackedStore`,
`EcsTagStore`, `EcsView`, `EcsQuery`, `EcsSystem`, `EcsScheduler`,
`EcsReaperSystem`, `EcsCapacityPolicySystem`, `SimulationClock`,
`UniformSpatialGrid`, `AngleMath`, а з відладкової частини — `EcsInspector`,
`EcsFrameRecorder`, `EcsFrameStats`, `EcsDiagnostics`, `EcsReport`.

Якщо якесь із них уже зайняте, Godot повідомить про помилку — перейменуйте
`class_name` у відповідному файлі аддона. Усередині бібліотеки ці імена ніде не
використовуються рядком, тому перейменування безпечне.

## Словник

Терміни, які зустрічаються в усіх розділах.

| Термін | Значення |
|---|---|
| **Сутність (entity)** | Просто ціле число — ідентифікатор. Не об'єкт, не нода, не клас. |
| **Компонент (component)** | Чисті дані, прив'язані до сутності. Позиція, здоров'я, швидкість. |
| **Система (system)** | Чиста логіка, що читає й пише компоненти. Без власного стану. |
| **Світ (world)** | Розподільник ідентифікаторів сутностей і реєстр сховищ. |
| **Сховище (store)** | Контейнер даних одного типу компонента для всіх сутностей. |
| **Щільний слот (dense slot)** | Індекс усередині щільного масиву сховища. Не дорівнює id сутності. |
| **Sparse set** | Структура з двох масивів, що дає і щільний обхід, і пошук за O(1). |
| **Swap-remove** | Видалення за O(1): останній елемент переїжджає на місце видаленого. |
| **Structural change** | Зміна складу: створення, знищення, attach, detach. |
| **Handle** | Безпечне посилання на сутність, що переживає кадри. |
| **Broadphase** | Структура для швидкої відповіді «хто поруч». |
